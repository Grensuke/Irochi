# Irochi — Frontend

**SIH 2026 — Problem Statement SIH26145**

The React + Vite + TypeScript frontend product shell for the Irochi threat-detection system. It provides security intelligence dashboards, alert review, and network telemetry visualization.

## Architecture & Integration Status

The frontend is currently in an **Active Infrastructure Integration** phase.

### Real Integration
The following features are connected to the live backend pipeline, displaying actual data generated by the active detectors and saved to PostgreSQL:
- **Alerts Page & Alert Detail View** (via REST API)
- **Live Feed** (via WebSocket from Redis Pub/Sub)
- **Global Dashboard Summary** (via REST API)

### Mock / Demo Data
The following features currently use mock synthetic data for demonstration and layout validation purposes:
- **Network Page** (Simplex Data-Diode Flow Dynamics visualizer)
- **Analytics Page** (Historical trends charts)
- **Settings** (UI only, no persistence)

## Major Components & Features

- `MeniscusNavbar`: Fluid liquid dock navigation for the app shell.
- `VerticalMeniscusRail`: Collapsed sidebar liquid rail.
- `DiodeFlowVisualizer`: Visualizes simplex data-diode flow dynamics (currently using synthetic data).
- `AlertTable` & `AlertDetail`: Interface for analysts to review, investigate, and triage detected threats.
- `LiveFeed`: Real-time streaming feed of new alerts.

## Running with Docker (Recommended)

The frontend is configured to run inside a Docker container orchestrated by the root `docker-compose.yml`. This automatically routes API requests to the backend container.

```bash
cd ..
docker compose up frontend
```
The application will be available at `http://localhost:5173`.

## Local Development Setup

If you are developing the frontend locally without Docker:

```bash
cd frontend
npm install
npm run dev
```

### Proxy Configuration
During local development, `vite.config.ts` proxies all API requests starting with `/api` to the backend. By default, it uses the `PROXY_TARGET` environment variable. Ensure your local `.env` file points to the running backend (e.g., `PROXY_TARGET=localhost:8000`).

## Build for Production

```bash
npm run build
```
Note: In a production environment, you will need a reverse proxy (like Nginx) to serve the static files and handle API/WebSocket routing to the backend, as the Vite dev server proxy is not used.
